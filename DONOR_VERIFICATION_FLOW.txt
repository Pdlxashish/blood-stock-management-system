║                              KEY ENDPOINTS                                     ║
╚═══════════════════════════════════════════════════════════════════════════════╝

📥 GET  /api/donors/pending              → List pending donors
📊 GET  /api/donors/verification-stats   → Get statistics
✅ PUT  /api/donors/:id/approve          → Approve a donor
❌ PUT  /api/donors/:id/reject           → Reject a donor
📋 GET  /api/donors                      → List all donors (filtered)
👤 GET  /api/donors/:id                  → Get single donor
➕ POST /api/donors                      → Create donor (sets PENDING)

╔═══════════════════════════════════════════════════════════════════════════════╗
║                              SECURITY NOTES                                    ║
╚═══════════════════════════════════════════════════════════════════════════════╝

🔒 Two-Step Verification:
   1. User registers → Creates account
   2. Admin approves → Grants access

🔍 Audit Trail:
   - Who verified (verifiedBy)
   - When verified (verifiedAt)
   - Why rejected (rejectionReason)

🛡️ Access Control:
   - Pending donors cannot access admin features
   - Only verified donors can donate blood
   - Rejected donors are blocked from system

📝 Documentation:
   - All actions are logged
   - Rejection reasons are required
   - Verification history is maintained
